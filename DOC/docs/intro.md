# 企业中台与微服务

ESCore 的企业中台不是一套“为了微服务而微服务”的重型集群，而是把企业实时应用最常见的公共能力沉淀下来，再通过清晰的领域边界组织业务代码。

它同时解决两个问题：

- **连接问题**：长连接、房间、消息广播、在线状态、多实例扩展；
- **业务问题**：账号、商户、门店、订单、支付、权限、日志、任务、设备与 AI 接入。

在这个基础上，你可以从单体应用起步，也可以随着业务增长，把领域模块拆成独立服务。

## 适合谁

| 角色 | 可以做什么 |
| --- | --- |
| 独立开发者 | 用一套可运行的基础框架，快速做出实时应用或 SaaS 原型 |
| 创业团队 | 复用账号、权限、订单、支付与消息能力，减少从零搭建的成本 |
| 企业研发团队 | 作为内部实时业务底座，统一通信协议、领域模型与部署方式 |
| 交付型团队 | 在稳定底座上叠加行业模块，把精力放在客户真正需要的能力上 |

## 能力地图

| 领域 | 已有基础 | 可扩展方向 |
| --- | --- | --- |
| 实时通信 | uWebSockets.js、Socket.IO、房间广播、Redis Adapter | 消息可靠性、离线消息、消息审计 |
| 账号与权限 | 用户、角色、资源、JWT、接口鉴权 | SSO、组织架构、数据权限、多租户 |
| 商户与门店 | 商户、门店、运营后台 | 连锁管理、区域代理、结算规则 |
| 交易与支付 | 订单、支付、回调与日志 | 优惠券、退款、对账、分账 |
| 设备接入 | MQTT 5、EMQX、心跳与指令回执 | 设备影子、OTA、规则引擎 |
| 文件与消息 | 对象存储、消息收发 | 多媒体处理、内容审核、归档 |
| AI Agent | 模型配置、流式结果推送 | 工具调用、知识库、工作流编排 |
| 工程化 | TypeScript、PM2、Nginx、Docker | 可观测性、灰度发布、自动化测试 |

## 服务是怎么组织的

ESCore 当前以**模块化单体 + 可水平扩展的实时通道**为主：

```text
浏览器 / 桌面端 / App / 小程序 / IoT 设备
                    │
          HTTPS / WSS / MQTT
                    │
        ┌───────────┴───────────┐
        │  API 网关 / Nginx      │
        │  JWT · 限流 · 路由     │
        └───────────┬───────────┘
                    │
   ┌────────────────┼────────────────┐
   │                │                │
HTTP API :3011   实时通道 :3012    EMQX :1883
Express           Socket.IO        IoT 设备
   │                │
领域模块          Redis Adapter
用户/商户/订单     多实例广播
支付/权限/任务
   │
MySQL / Redis / 对象存储 / 消息队列
```

这种组织方式适合大多数中小规模企业应用：部署简单、调试直接、领域边界清楚。当某个模块的连接量或业务复杂度显著增长时，再按领域拆出独立服务，而不是一开始就引入大量分布式复杂度。

## 设计原则

1. **先能跑，再扩展**：默认配置可以本地启动，生产环境再逐步增加 Redis、EMQX、PM2 多实例与 Nginx。
2. **领域边界优先**：账号、交易、设备、文件、AI 等能力按领域组织，避免所有逻辑堆在一个入口。
3. **协议稳定**：HTTP、Socket.IO 与 MQTT 的路径、端口和鉴权方式保持清晰，终端可以独立演进。
4. **安全默认开启**：JWT、权限校验、限流、Origin 白名单与密钥外置应该作为上线前的必选项。
